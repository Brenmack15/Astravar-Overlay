## Phase 5 contract and remaining release gates

1. Define a versioned manifest binding the continuity, authority and epoch, source cut-off, schema and normalization versions, record identity/revision, timestamps of known kinds, object lengths, digest algorithm, counts, visibility, explicit exclusions and unknown values. Keep raw legacy files and old receipt IDs separately addressable. Include a map from stable source identities to canonical actors, forms, item definitions/instances, wallets, resource pools, histories and media.
2. Read originals without changing them. Verify each artifact, size limit and declared family; stage only in an isolated destination. Produce counts for mapped, retained-source-only, identical, conflicted, held and unavailable rows. Dry run is read-only. Distinguish a missing family from an empty family. Reject ambiguous continuity membership, missing required dependencies, receipt or command collisions and conflicting committed snapshots. Never infer ownership, temporary HP, spent currency, a resource refill or a historical timestamp.
3. Preserve historical ledger and mechanical-source records as evidence, then verify native vs. cloud parity for stable identities, base/effective stats, forms, separate pools, exact wallet denominations, ownership, stack conservation, equipped effects, variants, spell slots, receipts, media and objectives. Importing a receipt, acquisition or cast must add zero new gameplay events.
4. Bind owner review to the exact manifest, reviewed rows, destination revision and authority epoch. Seal or explicitly resolve in-flight work. Commit in a transaction with deterministic idempotency, and verify via independent reads after restart. Roll back a failed run atomically. A later recovery must refuse superseded pre-cutover state or safely retain and reconcile subsequent legitimate commands. Document recovery by object store as well as database.
5. Keep installation, staging, import and authority activation separate. Installation must support a pre-migration state and preserve original Room data and signing identity. Only an explicit, independently verified Phase 7 approval can switch an existing continuity. Engineering acceptance exercises these paths on synthetic fixtures.
6. Test partial or missing files, changed objects, overlapping identities, repeated command deliveries, epoch mismatch, approvals, low space/cancellation, restore and source retention. A fresh export of an already restored dataset should yield the same scoped entities and history, plus declared administrative receipts. Require an Android in-place upgrade from frozen code 58, re-opened storage comparison and separate Android 17 evidence.

## Isolated migration and recovery procedure

Run `python3 tools/ascension_migrate.py --help` from a checkout containing the matching bundled Worker schema and PNG codec. The local tool requires Python 3.11 or later, SQLite JSON support and Node 24 for the service rehearsal. The optional encrypted transport uses Python `cryptography.fernet`. All paths in the following example are under an owner-private directory containing synthetic test inputs.

| Operation | Evidence and behavior |
| --- | --- |
| `inspect-legacy INPUT --owner O --continuity C` | Reports declared and absent collections, row counts, source identity, SHA-256, mapping target or hold reason. A reviewed world record receives a token bound to the exact input bytes, row identity, owner and continuity. |
| `convert-legacy INPUT PACKAGE --owner O --continuity C` | Builds a new cloud recovery ZIP after every nonempty native row has a known disposition. Pass a separate `--shared-wallet ID` for a verified shared, unassigned wallet. For approved player-known records without native continuity membership, pass each exact `--known-record TOKEN` from inspection. |
| `compare-legacy EARLIER LATER --owner O --continuity C` | Compares family, physical or composite ID, native revision and row digest. Distinct events with the same resulting balance retain separate identities. A same-revision difference requires review. |
| `mapping-template --source INPUT --owner O --continuity C` | Prints a versioned private review template containing each native source and row digest. Repeat `--source` for independent native exports and approved source facts. |
| `convert-reviewed MAPPING OUTPUT --source INPUT --owner O --continuity C` | Rebuilds typed canonical records, scoped relationships and any approved private PNGs from all supplied original bytes and the exact reviewed mapping. Produces a new validated recovery ZIP. |
| `mapping-identity --owner O --continuity C --family F --identity I --kind K --native-value V` | Derives a stable canonical alias for a store-local string identity. Repeat `--identity` for a native composite key. The source binding survives subsequent exports. |
| `parity NATIVE PACKAGE` | Independently compares recorded active HP and abilities, observed pool and slot balances, exact physical denominations, item quantity and ownership where the original format supplies those data. The report separates different, absent and unknown values and holds unsupported comparisons for review. |
| `extract-source PACKAGE NEW_FILE --sha256 DIGEST` | Verifies the package and creates a private, byte-identical copy of that original for its native restore workflow. An existing file is preserved. |
| `validate PACKAGE` | Checks package version, exact entry list, hashes, counts, original source mapping, media lengths, bounded decoding and relational consistency. Reopens a new database with the actual service schema and compares logical rows. |
| `init DIR --owner O --continuity C` | Creates a new private directory, authority epoch 1, mode staged and revision 0. An existing directory is refused. No network capability is required. |
| `preview DIR PACKAGE` | Verifies the source, compares the entire current tenant and outputs the exact staging approval digest. A populated destination requires separate reconciliation. |
| `apply DIR PACKAGE --approve DIGEST` | Writes a new SQLite generation, retains the prior generation, verifies reopened SQL and object bytes, then atomically publishes the staging pointer. Repeating an identical import returns the original receipt. |
| `status DIR` and `export DIR NEW_PACKAGE` | Reports authoritative mode and stored revision or creates a verified scoped package from a consistent transaction. Original and thumbnail bytes are stored by digest. Missing files, unexpected tables and in-progress image transfers stop export. |
| `rollback DIR` and `rollback DIR --approve DIGEST` | Previews and performs a return to the exact previous staged generation. Changed staging or earlier data blocks the return. Both generations remain available after success. |
| `cutover DIR` and `cutover DIR --approve DIGEST` | Reviews and commits an authority epoch increment only inside the rehearsal directory. The database checks legacy publication/proposal fences and the transaction records the decision. A closed cloud snapshot with pending requests can use `--carry-pending-for-review` at both steps to carry the exact pending identities into the new epoch. Owner review and a fresh grant are separate. |
| `seal PACKAGE ENCRYPTED --key-file KEY` and `unseal ENCRYPTED NEW_PACKAGE --key-file KEY` | Uses a private, independently stored Fernet recovery key. The key file contains a URL-safe base64-encoded 32-byte random key and requires an owner-only local mode. Authenticates, validates and checks the bytes before creating the destination. Preserve the key independently from the encrypted file. |

The staged store holds one owner and continuity. The tool obtains an exclusive filesystem lock and SQLite writer reservation during administrative decisions. Source bytes and typed rows are independently checked both before and after staging. A fresh grant is needed for each recovered client. A change after cutover requires another reconciliation. Prior backups can contain content permanently deleted later, including original source materials. Keep these private and apply retention and deletion policy separately.

### Preparing a reviewed graph

Use `mapping-template` for every original supplied to the final isolated rehearsal. Each decision binds the export SHA-256, native collection, stable row identity and SHA-256 of the parsed row. A source row may support several canonical records. Each normalized entity has a stable ID, kind, actor scope, title, active or archive state, positive revision and structured data. The owner approves the complete resulting package against the actual staging generation before installation.

Use the following dispositions on individual rows.

| Disposition | Effect |
| --- | --- |
| `map` | Publish specified player-known typed targets and record why the source belongs to this continuity. A scope or pending choice cannot be inferred from a character name. |
| `historical` | Preserve an eligible historical event, draft or archive row in original evidence. It creates no cloud transaction or current balance. |
| `foreign` | Retain independently proven foreign membership privately while excluding the row from gameplay. |
| `superseded` | Link a mutable older native version to its higher, mapped native revision by source, row identity and row digest. Both exact originals remain available. |
| `retain` | Keep a private unresolved row for review. Staging and rollback remain available. Both the local and provider rehearsals refuse authority cutover while this disposition exists. |

Format version 2 derives a player-visible actor source reference only from a reviewed, player-known native actor row whose identity witness established that canonical actor. The reference includes the native record family, witnessed ID, recorded revision and update time when available, and the names of mapped mechanical fields. The full private source, other actors, export hashes and review notes remain in the original recovery package. Original version 1 plans continue to regenerate their original entity bytes. A historical actor without a reviewed reference displays an unknown source.

Each `parity` entry identifies a native row and `sourcePath`, a canonical `target` and `targetPath`, and a transform. A path is an array of field names and array indexes. The `$json` step decodes one embedded native JSON string. `exact` preserves type and value. `lowercase` and `uppercase` normalize recorded enumerations. `omittedUnknown` can produce only null. `scopedIdentity` yields a stable derived ID for collisions and `canonicalRef` translates a verified native reference to that alias. Recorded Reforge numeric-effect targets, approved unconditional modifiers and native equipment states have narrowly defined schema translations. The historical Damage Defense converter checks the sealed payload discriminator and the distinct damageType property from commit f34bba0, the recorded defense kind and the accepted source. Unsupported nonmagical-only, conditional or uncertain variants require separate review. Item-owned pools are indexed by their original actor, physical item and pool identities. A reviewed import cannot collapse separate embedded pools. Flat maximum-HP and attack-damage effects preserve their source and signed amount. A supported native numeric attack bonus can bind a verified finite pool and cost on attack attempt. A damage bonus can bind the corresponding charge on confirmed hit. The mapping verifies the actor-scoped pool, trigger and source without spending a use. Unverified sources or unsupported effect prerequisites require a separate review. Native numeric balances, ability scores, HP, resource counts, item quantities and corresponding unknowns require source witnesses. Runtime registration and applicable definition contracts are checked directly by the backend validation module, without submitting commands. Any retained derived definition still requires rules parity using the relevant edition and fixture.

A class-level baseline can be restored from an independently identified, player-known progression source. Each track retains its ID, level, pinned edition, class source and any recorded subclass. The reviewed graph verifies the source fields and runs the same uniqueness and total-level checks as the authoritative service. A historical class name alone supplies no level allocation. A player-known lore record can retain an evidenced book, letter, map, research, document or lore classification. Older records can keep that field unknown.

The separate weapon format indexes current configuration, cores and installed payloads, templates, scrolls, slots, pending uses, projects, recent history and opaque native records. Each working row requires a decision. To preserve a retired Original Armor Archive solely as historical engineering evidence, add a fact with `values={"sourceRole":"original_armor_archive"}` bound to the exact `weapon.working` row. The review must then preserve every row in that file as historical. A working source with current mechanics can instead contribute reviewed playable records or retain individual unresolved rows. No native history event executes during import.

A separately reviewed `astravar-reviewed-source-facts` v1 envelope can supply a normalized classification that the native wire format does not encode, such as a finite pool type. Supply `owner`, `continuity` and a `facts` array. Each fact has a stable `id`, review `reason`, normalized `values`, and a `sourceBinding` containing the actual source digest, family, identity and row digest. Include the original file in the same package. An unbound classification, mismatched scope or attempted balance substitution fails validation.

Each edge identifies `from`, `relation`, `to` and the original row and field that establish its target. Required ownership, definition, resource and spell relationships are checked against their canonical types. An approved image entry specifies the exact source field, target and `approvedSha256` in the mapping's `media` array. The private bytes must decode through the same service codec available to authenticated clients. An artwork failure leaves the destination untouched.

A historical companion bond requires its original operator, that operator’s known class or homebrew feature, and the single occupied finite slot. A concentrated roll aid requires the recorded cast, caster, spell grant, target and expiry. The converter checks these references and preserves the cast-time configuration even if the spell definition was later revised. The isolated round trip checks the original occupied balance and the target’s calculated aid at two authority epochs. Import creates no gameplay receipt and contributes no new rolls or expenditure.

### Detached native archive recovery

For a complete native weapon archive up to 1 GiB, `detached-preview` validates the canonical package and streams the original ZIP. Its scoped manifest binds the whole-file SHA-256 and size of both inputs, the canonical manifest SHA-256 and table counts, the native working/index hashes, the native archive/original-file counts and byte totals, and the working record families. It verifies indexed payloads and preserved original-file chunks. This workflow preserves a recoverable historical file. Any current weapon mechanics still require their own source-backed mapping and owner review.

```sh
python3 tools/ascension_migrate.py detached-preview reviewed.zip weapon-history.zip
python3 tools/ascension_migrate.py detached-save reviewed.zip weapon-history.zip recovery-set --review-sha256 "$REVIEW_DIGEST"
python3 tools/ascension_migrate.py detached-verify recovery-set --review-sha256 "$REVIEW_DIGEST"
python3 tools/ascension_migrate.py detached-recover recovery-set recovered-weapon.zip --review-sha256 "$REVIEW_DIGEST"
```
