## Phase 5 contract and remaining release gates

1. Define a versioned manifest binding the continuity, authority and epoch, source cut-off, schema and normalization versions, record identity/revision, timestamps of known kinds, object lengths, digest algorithm, counts, visibility, explicit exclusions and unknown values. Keep raw legacy files and old receipt IDs separately addressable. Include a map from stable source identities to canonical actors, forms, item definitions/instances, wallets, resource pools, histories and media.
2. Read originals without changing them. Verify each artifact, size limit and declared family; stage only in an isolated destination. Produce counts for mapped, retained-source-only, identical, conflicted, held and unavailable rows. Dry run is read-only. Distinguish a missing family from an empty family. Reject ambiguous continuity membership, missing required dependencies, receipt or command collisions and conflicting committed snapshots. Never infer ownership, temporary HP, spent currency, a resource refill or a historical timestamp.
3. Preserve historical ledger and mechanical-source records as evidence, then verify native vs. cloud parity for stable identities, base/effective stats, forms, separate pools, exact wallet denominations, ownership, stack conservation, equipped effects, variants, spell slots, receipts, media and objectives. Importing a receipt, acquisition or cast must add zero new gameplay events.
4. Bind owner review to the exact manifest, reviewed rows, destination revision and authority epoch. Seal or explicitly resolve in-flight work. Commit in a transaction with deterministic idempotency, and verify via independent reads after restart. Roll back a failed run atomically. A later recovery must refuse superseded pre-cutover state or safely retain and reconcile subsequent legitimate commands. Document recovery by object store as well as database.
5. Keep installation, staging, import and authority activation separate. Installation must support a pre-migration state and preserve original Room data and signing identity. Only an explicit, independently verified Phase 7 approval can switch an existing continuity. Engineering acceptance exercises these paths on synthetic fixtures.
6. Test partial or missing files, changed objects, overlapping identities, repeated command deliveries, epoch mismatch, approvals, low space/cancellation, restore and source retention. A fresh export of an already restored dataset should yield the same scoped entities and history, plus declared administrative receipts. Require an Android in-place upgrade from frozen code 58, re-opened storage comparison and separate Android 17 evidence.

## Isolated migration and recovery procedure

Run `python3 tools/ascension_migrate.py --help` from a checkout containing the matching bundled Worker schema and PNG codec. The local tool requires Python 3.11 or later, SQLite JSON support and Node 24 for the service rehearsal. The optional encrypted transport uses Python `cryptography.fernet`. All paths in the following example are under an owner-private directory containing synthetic test inputs.

| Operation | Evidence and behavior |
| --- | --- |
| `inspect-legacy INPUT --owner O --continuity C` | Reports declared and absent collections, row counts, source identity, SHA-256, mapping target or hold reason. A reviewed world record receives a token bound to the exact input bytes, row identity, owner and continuity. |
| `convert-legacy INPUT PACKAGE --owner O --continuity C` | Builds a new cloud recovery ZIP after every nonempty native row has a known disposition. Pass a separate `--shared-wallet ID` for a verified shared, unassigned wallet. For approved player-known records without native continuity membership, pass each exact `--known-record TOKEN` from inspection. |
| `validate PACKAGE` | Checks package version, exact entry list, hashes, counts, original source mapping, media lengths, bounded decoding and relational consistency. Reopens a new database with the actual service schema and compares logical rows. |
| `init DIR --owner O --continuity C` | Creates a new private directory, authority epoch 1, mode staged and revision 0. An existing directory is refused. No network capability is required. |
| `preview DIR PACKAGE` | Verifies the source, compares the entire current tenant and outputs the exact staging approval digest. A populated destination requires separate reconciliation. |
| `apply DIR PACKAGE --approve DIGEST` | Writes a new SQLite generation, retains the prior generation, verifies reopened SQL and object bytes, then atomically publishes the staging pointer. Repeating an identical import returns the original receipt. |
| `status DIR` and `export DIR NEW_PACKAGE` | Reports authoritative mode and stored revision or creates a verified scoped package from a consistent transaction. Original and thumbnail bytes are stored by digest. Missing files, unexpected tables and in-progress image transfers stop export. |
| `rollback DIR` and `rollback DIR --approve DIGEST` | Previews and performs a return to the exact previous staged generation. Changed staging or earlier data blocks the return. Both generations remain available after success. |
| `cutover DIR` and `cutover DIR --approve DIGEST` | Reviews and commits an authority epoch increment only inside the rehearsal directory. The database checks legacy publication/proposal fences and the transaction records the decision. A closed cloud snapshot with pending requests can use `--carry-pending-for-review` at both steps to carry the exact pending identities into the new epoch. Owner review and a fresh grant are separate. |
| `seal PACKAGE ENCRYPTED --key-file KEY` and `unseal ENCRYPTED NEW_PACKAGE --key-file KEY` | Uses a private, independently stored Fernet recovery key. The key file contains a URL-safe base64-encoded 32-byte random key and requires an owner-only local mode. Authenticates, validates and checks the bytes before creating the destination. Preserve the key independently from the encrypted file. |

The staged store holds one owner and continuity. The tool obtains an exclusive filesystem lock and SQLite writer reservation during administrative decisions. Source bytes and typed rows are independently checked both before and after staging. A fresh grant is needed for each recovered client. A change after cutover requires another reconciliation. Prior backups can contain content permanently deleted later, including original source materials. Keep these private and apply retention and deletion policy separately.

### Versioned transport coverage

| Family | Transported evidence and checks |
| --- | --- |
| Continuity, records and links | Owner, continuity, source authority, epoch, revision and schema version. Every scoped entity retains its canonical identity, current mechanical JSON, life and revision. Links use the same scoped foreign keys as the service. The destination begins staged. |
| Commands, receipts, changes and deletions | Full immutable request/terminal pairing, revisions, typed changes, tombstones and pending approvals. Request and result headers refer to stored evidence parts or matching permanent-erasure markers. The exporter rejects missing segments, wrong digests, replacement with live content and incompatible change counts. |
| Private media | Upload reservations, owner preview records, durable cleanup intents and media entities. Both original and thumbnail must exist and decode at the recorded dimensions for surviving assets. Paths are derived from the scoped opaque upload identity. The ZIP contains no public asset URLs. |
| Identity and grants | Immutable historical grant decisions retain their event ID, epoch, subject and grant revision. A recovery package excludes account credentials, OAuth bearer data, device pairing secrets and active grants. Pair clients and authorize them in the new epoch. Legacy published mirrors, wake records and old outboxes require a separately verified engineering or account snapshot. |
| Original evidence | Native bytes, source SHA-256 and exact scope/mapping decisions remain addressable. The converter regenerates the mapping from the original bytes. Archive package validation includes SHA-256 for every encoded media or document entry declared by the original archive. |
| Encoding and limits | A version 1 ZIP declares each entry size, SHA-256 and count. Entries are capped at 64 MiB with a 256 MiB combined content cap. Migration refuses oversized sources for separate chunking and review. Encrypted packages preserve the exact verified ZIP on decryption. |

### Verification and operational dependencies

Run `python3 -m unittest discover -s scripts/tests -p test_ascension_migrate.py -v`. The suite uses temporary stores and fixed synthetic data. A test commits an actor through the actual Worker/MCP route, exports the entire store and restores to a fresh database. After reopening the service and issuing a new grant, it compares the complete immutable receipt and actor record across authority epochs. The suite also covers unknown denominations, changed source reviews, orphan relationships, duplicate deliveries, private originals/thumbnails, authenticated backup recovery, permanent-erasure proofs, retained pending approvals, failed staging and rollback refusal after gameplay.

This local adapter has no scheduled background backup. For isolated verification, create a verified export before each schema change or synthetic cutover. A deployment requires an owner-approved backup frequency, retention interval, encrypted storage and key-recovery procedure, provider snapshots covering SQL plus media, a tested restoration rehearsal, and an agreed recovery-time and recovery-point objective. The isolated smoke test supplies measured restoration behavior for its fixture. Production recovery timing, full legacy mechanical parity and handset upgrade acceptance remain separate release evidence.
