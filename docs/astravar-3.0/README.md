# Astravar 3.0 — Project Reforge

Implementation branch: `feat/astravar-3.0-reforge`.
Verified source baseline: `852bbd48af9b6c70be5ce44d5f898d1224ca0e7c`, the unmerged 2.4.0/code41 prompt-management branch. `main` contains only the historical initial repository and is not a viable implementation baseline. Earlier recovery, player-first, Cloudflare/Pushy, conflict-verifier and prompt changes are ancestors and retained.

Reforge is a major native Android change. It preserves the permanent release package, original signing configuration, historical stores and formats, accepted weapon engine, artwork, private connection, anonymous fictional sandbox restrictions and all original branches/PRs. Version defaults advance to `3.0.0-rc1`/42; that is a source candidate version, not proof of an installed or owner-signed release.

## Deliverable map

- `audit.md`: current-state findings, prioritized problems, implementation status.
- `beyond-research.md`, `functional-parity.md`, `official-interoperability.md`: actual interface/video research, scope limits and legitimate alternatives.
- `design.md`: navigation, visual system, components, accessibility.
- `rules-engine.md`: typed effects, calculations and gameplay contracts.
- `migration.md`: existing-store preservation and explicit reviewed local adoption.
- `verification.md`, `security-performance.md`, `release.md`: executed evidence and remaining gates.
- `CHANGELOG.md`, `known-limitations.md`, `checkpoint.md`: delivered changes, remaining milestones and exact continuation.
- `evidence/`: permissible UI evidence, with its source and limitations identified.

## Acceptance and authority

The target is one full ordinary session with native checks, saves, attacks, damage, equipment-derived statistics, spells/resources, companion management and readable campaign records. Code alone does not establish this outcome. Tests A–L from the owner directive are tracked in verification; features requiring account access, unavailable signing material or physical hardware stay explicitly unverified.

The new rules workspace requires a reviewed adoption of existing records. It is local-only and does not silently replace Android's existing authoritative campaign records or connect new mechanics to a production service. Existing campaign/weapon saves and the new workspace must be backed up through their respective export paths. A production canonical cutover, protected-branch merge, release publication and phone installation remain separate owner decisions.

No commercial rules corpus or proprietary D&D Beyond art/code is copied. User-authored structured mechanics and versioned exceptions are supported independently of the narrative text.
