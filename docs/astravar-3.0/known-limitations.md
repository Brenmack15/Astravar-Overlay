# Remaining scope and concrete continuation milestones

This candidate is a substantial native implementation, not a declaration of complete D&D Beyond parity or a canonical campaign cutover. Executed acceptance belongs in verification.md; installed-device acceptance is distinct from source tests and APK inspection.

| Remaining capability | Current behavior | Next milestone and acceptance |
|---|---|---|
| Complete adoption of existing mechanics | Baseline copy preserves source IDs/content and imports reviewed numeric baselines and placed items. Training, movement/senses, spells, features and resource uses require structured setup; the adoption preview and source-copy sheet disclose this. Confirmed simple companion attacks have a separate reviewed converter. | Reconciliation wizard with typed per-field candidates, exact source revisions, no inferred rests, unknown preservation and a full session replay using reconciled fixtures. |
| Synchronization of new mechanics | New character workspace, dice and notes are local-only. Existing authenticated legacy campaign synchronization remains separate. | Versioned private protocol adapter for typed records, grants, outbox/receipts/conflicts, independent Android readback and offline retries. Prepare and test without production changes; authoritative cutover/deployment requires the appropriate separate approval. |
| Combined inventory authority | Existing ledger, ownership/container/currency/crafting workflows remain intact. Reviewed local equipment definitions are separate copies, not an automatic bidirectional inventory mirror. | Reconcile each stable item instance to one canonical identity; test transfers, containers, consumption, composite donors and restart without duplicate effects or transactions before any cutover. |
| Complete class builder and catalog | Identity, training, feats/features and confirmed advancement are editable. The pinned legacy Infusions Artificer has slot/preparation calculations. New class features and spells are not automatically awarded from a commercial catalog. | Licensed versioned class/species/feat definitions and advancement choice validation; multiclass tests and explicit edition compatibility decisions. |
| Companion transformations | Independent companion sheets and confirmed attack conversion work. Existing specialized companion source records remain accessible. | Accepted generic form contracts with explicit separate/shared HP, damage carryover, armor pool, equipment, reaction and resource policies. Do not guess Eek's or Veyrath's current mechanics from old references or proposals. |
| Universal mechanical authoring | Typed engine supports more conditions/effects than the compact item editor exposes. Narrative text never becomes an active bonus. | Dedicated reviewed effect editor for remaining conditional/contextual and composite properties, with qualifier, source, activation and suppression previews. |
| All spell/encounter adjudication | Cast previews consume configured slots/charges and manage concentration/turn rules. Components, target geometry and narrative spell effects require the player/DM; higher-slot text does not automatically produce every spell's damage. | Typed spell effects/upcast components, component eligibility and concentration-save workflows; preserve DM-controlled target decisions and explicit dice ownership. |
| Additional rule edge cases | Core and class versions are pinned. Complete legacy bonus-action casting restrictions, ritual intervals and world-state rest eligibility are not fully automated. | Focused official-source review and adversarial tests for each supported rules family before advertising universal automation. |
| Source document editing | Native character notes autosave with guarded recovery and one-step undo. Legacy source/NPC/project editors retain explicit save and recovery behavior. | Transactional committed autosave/undo across remaining document types, with concurrent revision and failed-save recovery tests. |
| Embedded rich media | Native rich text renders safe links, tables and Notion mentions. Remote images open only after a tap; selected character portraits use local document access. | Bounded private image cache, offline behavior, content limits and access-controlled internal record previews. |
| Official PDF migration | No supported public D&D Beyond character API contract was verified. Manual structured editing and validated local JSON backups work. | User-selected official PDF parser with field-by-field preview, retained original bytes, edition/source reconciliation and tests against actual owner-provided exports. No private endpoint scraping or account credentials. |
| Physical Samsung acceptance | APK identity, automated checks and any emulator results are recorded independently. Android client metadata does not inspect the phone. | With separate installation approval, verify actual installed package/version/certificate, safe in-place update, local record readback, Android 17 layout, TalkBack, battery/Doze and actual owner sync scopes. |

No task in this table authorizes clearing app data, rotating the owner key, publishing a production release, merging a protected branch, altering confirmed campaign history or exposing private records. The original private signing material stays outside Git/CI and remains separate from distributable APKs and verification artifacts.
